# MAPS

**MAPS: Multiscale Source Detection in Multilayer Affiliation Networks**

Last Updated: Sept 20, 2026

## Overview

This repository contains the code, data, and experimental results for **MAPS**, a
multiscale framework for locating the failed (source) tasks of a project from a
binary execution snapshot of its task network.

A snapshot marks each node as `status = 0` (completed / healthy) or
`status = 1` (not completed / failed). Given such a snapshot, a source-detection
method estimates the set of nodes whose failure explains the observed state.

The experiments cover the following settings:

- **Problems**: `single` (one source) and `multiple` (several sources).
- **Noise scenarios**:
  - `normal` — noise-free propagation;
  - `PP` (probabilistic propagation) — a failed node propagates the failure to
    each successor with probability `P_r`;
  - `OE` (observation error) — a fraction `P_e` of node states is randomly
    flipped in the snapshot.
- **Frameworks**:
  - `SL` — single-layer source localization on one network layer;
  - `MLSL` — multiscale layer-by-layer localization: sources are first located
    on a coarse upper layer, then refined on the subgraph of the corresponding
    lower-layer nodes. `MAPS` is the multiscale ILP framework (`MLSL` + `ILP`).
- **Methods**:
  - `ME` — minimal-element / mini-set method (implemented as `mini_set`):
    zero-in-degree nodes of the failed subgraph;
  - `LP` — label propagation based source identification, i.e. `LPSI`
    (Wang et al., AAAI 2017) and its degree-aware variant `LPSI_deg`
    (Hu et al., Physica A 2025);
  - `ILP` — minimum source cover solved with the Gurobi optimizer
    (hard / soft constrained formulations, with tolerance for uncovered
    failures and touched healthy nodes).

## Framework Structure

Every network node is identified by a 6-digit hierarchical ID, where each pair
of digits represents one level:

| Level | ID pattern | Example  | Meaning                                          |
|-------|------------|----------|--------------------------------------------------|
| L1    | `xx0000`   | `010000` | first-level (coarsest) node                      |
| L2    | `xxxx00`   | `010100` | child of L1 node `010000`                        |
| L3    | `xxxxyy`   | `010101` | child of L2 node `010100` (finest granularity)   |

The parent of an L3 node is obtained by truncating its last two digits to `00`
(`010101 -> 010100`), and the parent of an L2 node by truncating its last four
digits (`010100 -> 010000`).

The three network layers are referred to as:

- **G1** — the 17-node first-level network;
- **G2** — the 192-node second-level network;
- **G3** — the 1456-node third-level network, generated by refining every node
  of G2 into 5–10 subnodes (see `gene_large_graph.py`).

## Data Description

The input data is stored in the `data` directory:

| File | Nodes / Edges | Columns |
|------|---------------|---------|
| `nodelist_L1.xlsx` | 17 nodes | `id`, `label`, `time`, `cost` |
| `edgelist_L1.xlsx` | 24 edges | `source`, `target`, `time`, `relation` |
| `nodelist_L2.xlsx` | 192 nodes | `id`, `label`, `time`, `cost` |
| `edgelist_L2.xlsx` | 239 edges | `source`, `target`, `relation` |
| `nodelist_L3.xlsx` | 1456 nodes | `id` |
| `edgelist_L3.xlsx` | 1573 edges | `source`, `target` |

`nodelist_L2_status.xlsx` and `status_L2.xlsx` are L2 snapshots that additionally
carry a node `status` column (`0` = completed, `1` = not completed).

All node IDs are read as strings to preserve leading zeros.

## Code Description

### Core libraries

- **`lpsi.py`** — implementation of `LPSI` and `LPSI_deg` label propagation
  source identification. Directed task DAGs are converted to undirected graphs
  by default; `source_count=None` applies the original multiple-source local
  maximum rule, while a positive `source_count` returns the top-ranked failed
  nodes (used by the single-source experiments).
- **`guro_opt.py`** — ILP formulations of the minimum source cover problem:
  `ilp_min_source_cover_hard`, `ilp_min_source_cover_soft`,
  `ilp_min_source_cover_soft_prob`, and the dynamic variants used by the
  multiple-source multiscale experiments. Gurobi is imported lazily, so the
  non-ILP methods run without `gurobipy` or a license.

### Experiment drivers

The scripts are named `{SL,MLSL}_{single,multiple}_{OEPP,anynoise}.py`:

- `SL_*` — single-layer experiments (the layer is set by `L_num`; the shipped
  drivers use L3);
- `MLSL_*` — multiscale layer-by-layer experiments (`L_num=[upper, lower]`,
  e.g. `[2, 3]` for G2 → G3);
- `single` / `multiple` — source-count setting;
- `*_OEPP.py` — parameter-sweep drivers (the swept noise type and parameter
  list are set inside the script);
- `*_anynoise.py` — drivers that loop over all noise types.

The detection method is selected with the `method_list` variable
(`'mini_set'`, `'label_prop'`, `'LPSI'`, `'LPSI_deg'`, `'ILP'`), and the noise
scenario with `noise_list` (`'normal'`, `'prob_prop'`, `'obs_error'`). Random
seeds are fixed to `0` for reproducibility. Results are written to `results/`.

### Utilities

- **`gene_large_graph.py`** — refines every node of the base graph into 5–10
  subnodes to generate the large-scale graph G3 from G2 (reads the base-graph
  files named `nodelist_detailed.xlsx` / `edgelist_detailed.xlsx`, writes
  `nodelist_large.xlsx` / `edgelist_large.xlsx`).
- **`calc_time.py`** — computes the project completion time from earliest finish
  times along the topological order of the DAG.
- **`plot_res.py`** — draws the QD–TD scatter plots (panels for G2 and G3) that
  compare `MS-ME`, `MS-LPSI`, and `MAPS` against their single-scale baselines.
- **`sensitivity.py`** / **`sensitivity_2.py`** — sensitivity analysis of MAPS
  relative to single-scale ILP: QD–TD trajectories over
  `P_r ∈ [0.70, 1.00]` (PP) and `P_e ∈ [0.00, 0.30]` (OE), exported as figures
  and `results/*.xlsx` data files.
- **`transfer_form.py`** — utility for converting `.xlsx` tables to UTF-8 CSV
  (with or without BOM).
- **`test.py`** / **`test1.py`** — development / plotting scratch scripts.
- **`test_lpsi.py`** — unit tests for `lpsi.py`
  (`python -m unittest test_lpsi`).

## Evaluation Metrics

- **Precision** — fraction of instances whose located source set exactly matches
  the true source set (single-source experiments).
- **F1-score** — set-level quality of the located sources (multiple-source
  experiments).
- **Time** — wall-clock runtime of a method in seconds.
- **QD (quality difference)** — `(Q_MS - Q_SS) / Q_SS`, i.e. the relative
  quality change of the multiscale method w.r.t. its single-scale baseline.
- **TD (time difference)** — `(T_MS - T_SS) / T_SS`, the relative runtime change.
- **EI (efficiency improvement)** — `-TD / |QD| - 1`.

## Results Description

The output data is stored in the `results` directory:

- **JSON result files** — 24 files named
  `{SL,MLSL}_{single,multiple}_{ME,LP,ILP}_{OE,PP}_L3.json`. Each file contains
  the swept parameter list (`error_prop_list` or `prop_prob_list`, 51 values
  with step `0.01`) together with the corresponding `precision` and `time`
  arrays.
- **`quality_data.xlsx` / `time_data.xlsx`** — aggregated precision / F1 and
  runtime tables with one column per
  `{SL,MLSL}_{single,multiple}_{ME,LP,ILP}_{OE,PP}` combination.
- **`results.xlsx`** — manuscript summary tables for single-layer (单层溯源) and
  layer-by-layer (逐层溯源) localization across methods
  (极小元法 / 标签迭代 / ILP) and scenarios (无噪音 / 观测误差 / 概率传播).
- **`test_res.xlsx`** — single-case SL vs MLSL time / quality comparison.
- **`maps_qd_td_curves_data.xlsx`, `maps_qd_td_sensitivity_data.xlsx`,
  `qd_td_sensitivity_data.xlsx`** — QD / TD data behind the sensitivity figures.

## Requirements and Usage

Required packages: `networkx`, `numpy`, `pandas`, `matplotlib`, `scipy`, and
`openpyxl` (for reading/writing Excel). The ILP methods additionally require
`gurobipy` and a valid Gurobi license.

Run the scripts from the repository root, since all data and result paths are
relative:

```bash
python SL_single_OEPP.py        # single-layer, single-source PP sweep
python MLSL_single_OEPP.py      # multiscale (MAPS), single-source PP sweep
python SL_multiple_OEPP.py      # single-layer, multiple-source OE sweep
python MLSL_multiple_OEPP.py    # multiscale (MAPS), multiple-source OE sweep
python plot_res.py              # QD-TD scatter plots
python sensitivity.py           # MAPS QD-TD sensitivity figures
python -m unittest test_lpsi    # unit tests
```
